1. SCHEMA DESIGN & FUTURE-PROOFING
================================================================================

CURRENT SCHEMA ANALYSIS
-----------------------
Your proposed schema is good for basic use cases, but has limitations:

✅ STRENGTHS:
- Clear separation of concerns (Product vs Offer)
- Temporal validity (startDate, endDate)
- Priority system for conflict resolution
- Cascade delete maintains referential integrity

⚠️ LIMITATIONS:
- Single product per offer (can't do "Buy 2 Get 1")
- No quantity-based discounts
- No user segmentation (VIP, first-time buyers, etc.)
- No usage limits (first 100 customers)
- No minimum purchase requirements
- Discount value stored as Float (precision issues for currency)

RECOMMENDED ENHANCED SCHEMA
---------------------------

model Offer {

  // Basic Info
  name              String    // "Yalda Night Special", "Flash Deal"
  description       String?
  internalNotes     String?   // Admin-only notes

  discountValue     Decimal   @db.Decimal(10, 2)  // Use Decimal for precision

  minQuantity       Int       @default(1)
  maxQuantity       Int?      // null = unlimited
  minPurchaseAmount Decimal?  @db.Decimal(10, 2)
  
  // Temporal Validity
  startDate         DateTime  @default(now())
  endDate           DateTime
  timezone          String    @default("Asia/Tehran")

// Junction table for many-to-many Product-Offer relationship
model OfferProduct {
  id        Int      @id @default(autoincrement())

  @@unique([offerId, productId])
  @@index([productId])
  @@index([offerId])

2. DISCOUNT LOGIC: WHERE TO STORE PRICING DATA?
================================================================================

OPTION A: Store Calculated Prices in Offer
-------------------------------------------
Structure:
  Offer {
    originalPrice    Decimal
    discountedPrice  Decimal
    discountAmount   Decimal
  }

PROS:
✅ Fast reads - no calculation needed
✅ Historical accuracy - prices frozen at offer creation
✅ Simpler frontend logic

CONS:
❌ Data duplication
❌ Staleness risk - product price changes make offer prices wrong
❌ More storage space
❌ Harder to update bulk prices


OPTION B: Store Only Discount Rules (RECOMMENDED)
--------------------------------------------------
Structure:
  Offer {
    discountType   DiscountType
    discountValue  Decimal
  }
  
Calculate price at runtime:
  effectivePrice = product.price - (
    discountType === 'PERCENTAGE' 
      ? product.price * (discountValue / 100)
      : discountValue
  )

PROS:
✅ Single source of truth for prices
✅ Automatic adaptation to product price changes
✅ Minimal storage
✅ Easier bulk updates
✅ Less data inconsistency risk

CONS:
❌ Computation cost (minimal with indexing/caching)
❌ Need proper transaction handling


OPTION C: HYBRID APPROACH (BEST OF BOTH WORLDS)
------------------------------------------------
Structure:
  Offer {
    discountType         DiscountType
    discountValue        Decimal
    
    // Snapshot at creation (optional, for display)
    snapshotOriginalPrice  Decimal?
    snapshotDiscountAmount Decimal?
    
    // Computed at runtime
    get effectivePrice() { ... }
  }

STRATEGY:
1. Store discount RULES (type + value) - authoritative
2. Optionally snapshot prices at offer creation for reference
3. Always compute final price at runtime using current product price
4. Use snapshots only for admin analytics ("How much discount did we give?")

PROS:
✅ Best of both worlds
✅ Historical data for reporting
✅ Current prices for checkout
✅ Flexibility

RECOMMENDATION:
Use Option B (rule-based) for most cases. Add Option C (hybrid) only if you
need detailed financial reporting or want to show "original offer price" even
after product price changes.

4. CAROUSEL SELECTION ALGORITHM
================================================================================

GOAL: Show the most relevant, high-performing offers to maximize conversions.


MULTI-FACTOR SCORING ALGORITHM
-------------------------------

function selectOffersForCarousel(userId?: number, limit = 10) {
  const now = new Date();
  
  // Base query: Active, valid, featured offers
  let offers = await prisma.offer.findMany({
    where: {
      isActive: true,
      isFeatured: true,
      startDate: { lte: now },
      endDate: { gte: now },
      OR: [
        { maxTotalUses: null },
        { currentUseCount: { lt: maxTotalUses } }
      ]
    },
    include: {
      products: {
        include: {
          product: {
            include: { category: true }
          }
        }
      },
      campaign: true,
      userSegments: true
    }
  });
  
  // Calculate score for each offer
  const scoredOffers = offers.map(offer => {
    let score = 0;
    
    // 1. PRIORITY WEIGHT (30%)
    score += offer.priority * 0.3;
    
    // 2. DISCOUNT ATTRACTIVENESS (25%)
    const avgDiscount = calculateAverageDiscount(offer);
    score += (avgDiscount / 100) * 25;
    
    // 3. URGENCY FACTOR (20%)
    const hoursRemaining = (offer.endDate - now) / (1000 * 60 * 60);
    if (hoursRemaining < 24) score += 20;
    else if (hoursRemaining < 72) score += 15;
    else if (hoursRemaining < 168) score += 10;
    
    // 4. STOCK AVAILABILITY (15%)
    const inStockProducts = offer.products.filter(
      p => p.product.stock > 0
    ).length;
    const stockRatio = inStockProducts / offer.products.length;
    score += stockRatio * 15;
    
    // 5. USER PERSONALIZATION (10%)
    if (userId) {
      const userSegmentMatch = checkUserSegmentMatch(userId, offer);
      if (userSegmentMatch) score += 10;
      
      const userCategoryAffinity = checkCategoryAffinity(userId, offer);
      score += userCategoryAffinity * 5;
    }
    
    // 6. REDEMPTION RATE (Bonus)
    // If offer has been used 50%+ of max, it's popular - boost it
    if (offer.maxTotalUses) {
      const redemptionRate = offer.currentUseCount / offer.maxTotalUses;
      if (redemptionRate > 0.5) score += 5;
    }
    
    // 7. MANUAL OVERRIDE
    if (offer.displayOrder !== null) {
      score = 1000 - offer.displayOrder; // Higher displayOrder = lower score
    }
    
    return { ...offer, score };
  });
  
  // Sort by score descending
  scoredOffers.sort((a, b) => b.score - a.score);
  
  // Diversity filter: Don't show 3+ offers from same category
  const diversified = diversifyByCategory(scoredOffers, 2);
  
  // Return top N
  return diversified.slice(0, limit);
}

COMPOUND INDEX RATIONALE:

- [isActive, isFeatured, startDate, endDate] allows queries like:
  WHERE isActive = true AND isFeatured = true (uses index)
  WHERE isActive = true (uses index)
  WHERE isFeatured = true (doesn't use index - not leftmost)


QUERY OPTIMIZATION
------------------

1. AVOID N+1 QUERIES

BAD:
const offers = await prisma.offer.findMany();
for (const offer of offers) {
  const products = await prisma.offerProduct.findMany({
    where: { offerId: offer.id }
  }); // N+1 queries!
}

GOOD:
const offers = await prisma.offer.findMany({
  include: {
    products: {
      include: { product: true }
    }
  }
}); // Single query with joins


2. USE SELECT TO LIMIT FIELDS

BAD:
const offers = await prisma.offer.findMany(); 
// Returns all fields including large text fields

GOOD:
const offers = await prisma.offer.findMany({
  select: {
    id: true,
    name: true,
    discountType: true,
    discountValue: true,
    products: {
      select: {
        product: {
          select: {
            id: true,
            name: true,
            price: true,
            images: true
          }
        }
      }
    }
  }
});

async function invalidateOfferCache(offerId: number) {
  // Clear specific offer cache
  await redis.del(`offer:${offerId}`);
  
  // Clear carousel cache (affects homepage)
  await redis.del('homepage:carousel:offers');
  
  // Clear product cache if offer affects it
  const offer = await prisma.offer.findUnique({
    where: { id: offerId },
    include: { products: true }
  });
  
  for (const { productId } of offer.products) {
    await redis.del(`product:${productId}`);
  }
  
  // Trigger ISR revalidation
  await fetch('/api/revalidate?path=/', {
    headers: { 'x-revalidate-secret': process.env.REVALIDATE_SECRET }
  });
}

DATA MIGRATION PLAN
-------------------

If you have existing products with real discounts:

1. Create a migration script to convert them to offers:

import { PrismaClient } from '@prisma/client';

const prisma = new PrismaClient();

async function migrateDiscountsToOffers() {
  const discountedProducts = await prisma.product.findMany({
    where: {
      listPrice: { not: null },
      price: { lt: prisma.product.fields.listPrice }
    }
  });
  
  for (const product of discountedProducts) {
    const discountAmount = product.listPrice - product.price;
    const discountPercentage = (discountAmount / product.listPrice) * 100;
    
    await prisma.offer.create({
      data: {
        name: `Existing discount - ${product.name}`,
        discountType: 'PERCENTAGE',
        discountValue: discountPercentage,
        startDate: new Date('2024-01-01'), // retroactive
        endDate: new Date('2026-12-31'), // far future
        isActive: true,
        isFeatured: false,
        products: {
          create: {
            productId: product.id
          }
        }
      }
    });
  }
}

2. Optional: Reset product.listPrice after migration
   (so offers become single source of truth)
